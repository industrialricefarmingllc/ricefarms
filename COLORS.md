# Colours: one matugen palette, a different "secondary" per surface

The rice does **not** use one global secondary accent. Every theme starts as a
single Material 3 scheme generated by **matugen** from the current wallpaper (or
from the colour picked in *Settings → Theme*). The shell, the terminals, the
compositor and the individual apps then apply their own rule to matugen's
`secondary` role. That is deliberate: one role number cannot be legible as a
terminal ANSI colour, a shell mark and a 1 px window border at the same time.

This document records the rules so a future change does not accidentally
"unify" them.

## 1. Source of truth

```
wallpaper / picked colour
        │
        ▼
matugen  (scheme + contrast + source index from matugen-options.sh)
        │  one M3 role set: primary, secondary, secondary_container, …
        ├── ~/.cache/quickshell/matugen.json        → Lucid shell
        ├── ~/.config/kitty/matugen-colors.conf     → kitty
        ├── ~/.config/foot/foot.ini.matugen         → foot
        ├── ~/.config/hypr/colors.{conf,lua}        → Hyprland chrome
        ├── ~/.config/opencode/themes/matugen.json  → OpenCode
        ├── ~/.config/btop/themes/matugen.theme     → btop
        ├── …/helium-matugen-theme/manifest.json    → Helium
        └── ~/.config/dunst/dunstrc                 → dunst
```

- `~/.config/lucid/matugen-options.sh` chooses the scheme (`scheme-tonal-spot`
  by default), contrast, theme colour and which dominant wallpaper colour to
  seed from. *Settings → Theme* writes those preferences.
- The wallpaper path is
  `~/.config/hypr/scripts/wallpaper/set-wallpaper.sh`: it asks matugen for the
  role set, caches it, writes every template and then hands delivery to
  `~/.config/lucid/theme-fanout.sh`.
- `~/.config/matugen/config.toml` is the template list. Every consumer below
  receives the **same** role set, so a wallpaper change recolours everything in
  one settled transaction.
- The shell reads `~/.cache/quickshell/matugen.json` directly. It is the only
  consumer that post-processes the roles in QML; the others receive rendered
  files.

The templates are intentionally dumb: they copy roles. The interesting
decisions happen in the consumers.

## 2. What each consumer does with "secondary"

| Consumer | Value it actually shows | Implementation |
| --- | --- | --- |
| **Lucid shell** | Primary hue rotated **−20°**, saturated, at the *tone* of matugen's secondary. Its "secondary container" is the shared primary container, not matugen's `secondary_container`. | `payload/quickshell/Theme.qml` → `_secondaryHue`, `secondary`, `secondaryContainer` |
| **Lucid bar** | Same rule (a second standalone copy of the palette singleton). | `payload/quickshell/lucidbar/Theme.qml` |
| **kitty** | matugen `secondary` in `color3`, `secondary_container` in `color11` and the selection, then the whole primary/secondary/tertiary family is pushed to **full chroma** by `kitty-tune.py`. Background is Lucid's `bgOpaque`, not matugen's surface. | `payload/matugen/templates/kitty-colors.conf` + `payload/lucid/kitty-tune.py` + `payload/kitty/lucid-surface.conf` |
| **foot** | raw matugen `secondary` as ANSI `regular5`; no saturation pass. | `payload/matugen/templates/foot.ini` |
| **Hyprland window chrome** | raw matugen `secondary` as `accent2`; the active border is a primary→secondary gradient, each stop mixed toward the inactive colour so it does not glow. | `payload/matugen/templates/hyprland-colors.lua` + `payload/hypr/hyprland.lua` |
| **Helium** | `secondary_container` for the tab strip, `on_secondary_container` for tab text. | `payload/matugen/templates/helium-theme.json` |
| **OpenCode** | raw matugen `secondary` for `secondary`/`warning`, diff-added, syntax functions and markdown accents; its background is re-pinned to Lucid's `bgOpaque`. | `payload/matugen/templates/opencode.json` + `payload/lucid/app-surface-sync.sh` |
| **btop** | raw matugen `secondary` as process-misc and the mid stop of every gauge. | `payload/matugen/templates/btop.theme` |
| **GTK 3/4** | no secondary role: primary is the only accent. Surfaces match the shell. | `payload/lucid/app-surface-sync.sh` |
| **dunst** | no secondary role: primary frames, error container for critical. | `payload/matugen/templates/dunstrc` |

## 3. The Lucid shell rule (the unusual one)

`Theme.qml` keeps matugen's roles as `cPrimary`, `cSecondary`, … but the public
`secondary` property is **derived**:

```qml
readonly property real _secondaryHue: -20
readonly property color secondary:
    root.containerFill(root.withHue(root.cPrimary, root._secondaryHue),
                       root.toneOf(root.cSecondary))
```

- `withHue()` holds the primary's tone and chroma and spins its hue by −20°.
- `containerFill()` rebuilds the colour at HSL lightness 0.5, floors its
  saturation at `_containerSatFloor` (0.22), then re-tones it.
- The final tone comes from matugen's `secondary`, so the shell stays on the
  wallpaper's intended elevation even though the hue is its own.

The result is an accent that sits beside the shell primary (a teal next to a
blue, for example) instead of repeating the terminal's vivid secondary. It is
used for marks, checkable buttons, chips and icon buttons
(`Theme.secondary`, `Theme.fgSecondary`).

Two related deliberate couplings:

- `secondaryContainer` is **not** matugen's `secondary_container`. It is
  `accentContainer`, which is the same fill as `primaryContainer` and
  `tertiaryContainer`:
  `containerFill(primary_container, _containerTone, _cardSatFloor)`. Filled
  cards/buttons/badges share one colour on purpose; three different container
  hues on one screen looked unrelated. `errorContainer` remains its own fill.
- `tertiary` is the same construction spun **+14°** from primary
  (`_tertiaryHue`), at tone 80 dark / 42 light. The raw matugen tertiary is
  still what decides whether the `success` state is green
  (`isGreenish(cTertiary)`).

`payload/quickshell/lucidbar/Theme.qml` carries the same constants and formula.
Change both or the bar and the rest of the shell will disagree.

## 4. Terminals: raw colour, then full chroma

The kitty template writes matugen's roles verbatim:

```conf
color3   {{ colors.secondary.default.hex }}          # ANSI yellow slot
color11  {{ colors.secondary_container.default.hex }} # bright ANSI yellow
selection_background {{ colors.secondary_container.default.hex }}
```

After the template renders, `set-wallpaper.sh` runs `kitty-tune.py` once over
`~/.config/kitty/matugen-colors.conf`. For every hex that belongs to the
primary/secondary/tertiary family, it raises saturation to 1.0 (factor 4,
minimum 1.0) while holding hue and lightness. `color3` therefore becomes a
vivid version of matugen's secondary — usually much more chromatic than the
shell's −20° accent.

The terminal **background** is deliberately not matugen's `surface`:
`app-surface-sync.sh` writes `lucid-surface.conf` with Lucid's `bgOpaque`
(`Theme.mContainer`), and `kitty.conf` includes it last. Accents come from
matugen; the window surface comes from the shell so kitty, GTK and Lucid sit on
the same colour.

`foot` uses the same raw role (`regular5 = secondary`) but has no
`kitty-tune.py` pass, so foot's secondary stays muted. This is expected.

Static themes (pywal / imported schemes applied by `apply-theme.sh`) write
their kitty palette directly and also skip `kitty-tune.py`; their secondary is
the palette's own.

## 5. Window chrome

`hyprland.lua` reads `accent` (primary) and `accent2` (secondary) from
`colors.lua`. It first calls `visible()` to lift/darken an accent until it
clears a luminance threshold, then mixes each stop a short way from
`inactive` toward the accent (18% dark, 14% light). The focused window border
is therefore a **blend** of the surface variant with primary→secondary, at full
opacity. It is intentionally quieter than the shell and the terminal.

## 6. Worked example

Using the light palette committed in the repo (wallpaper
`wallhaven-w5x2yq.png`, `primary #36618e`, `secondary #535f70`,
`secondary_container #d0e1fe`):

| Surface | Colour | Why |
| --- | --- | --- |
| Lucid shell `secondary` | `#276674` (teal) | primary hue 210.7° − 20°, at secondary's tone |
| Lucid shell `secondaryContainer` | `#003fa4` | shared primary container fill |
| kitty `color3` | `#0050c3` | matugen secondary saturated to full chroma |
| kitty `color11` / selection | `#d0e1fe` | matugen secondary container |
| Hyprland `accent2` | `#535f70` | raw matugen secondary, then blended |
| Helium active tab | `#d0e1fe` | matugen secondary container |
| OpenCode `secondary` / warning | `#535f70` | raw matugen secondary |
| btop gauge mid | `#535f70` | raw matugen secondary |

The shell and the terminal intentionally show different colours here. That is
the design, not drift. Exact values change with the wallpaper and with
matugen's contrast/scheme settings; the shell-only values above are computed
from the QML recipe and rounded.

## 7. Where to change what

| Want to change | Edit |
| --- | --- |
| Shell secondary hue offset | `_secondaryHue` in `payload/quickshell/Theme.qml` **and** `payload/quickshell/lucidbar/Theme.qml` |
| Shell tertiary hue offset | `_tertiaryHue` in both Theme.qml files |
| Shell card tone / chroma floor | `_containerTone`, `_containerSatFloor`, `_cardSatFloor` in both Theme.qml files |
| Terminal accent vividness | `kitty-tune.py` (`factor`, `min_s`, or the `strong` role list) |
| Which ANSI slot gets secondary | `payload/matugen/templates/kitty-colors.conf`, `foot.ini` |
| Window border colours | `payload/matugen/templates/hyprland-colors.{lua,conf}` and the mix in `payload/hypr/hyprland.lua` |
| Which app role gets secondary | that app's template under `payload/matugen/templates/` |
| App background vs shell surface | `payload/lucid/app-surface-sync.sh` |
| Scheme / contrast / seed colour | `payload/lucid/matugen-options.sh` and *Settings → Theme* |

## 8. Gotchas

- Generated files (`colors.lua`, `matugen-colors.conf`, `lucid-surface.conf`,
  `foot.ini.matugen`, `themes/matugen.json`, …) are outputs. Edit templates and
  scripts, not the generated copies in `payload/`; `install.sh --export`
  refreshes those from the live machine.
- `secondaryContainer` in the shell is **not** matugen's `secondary_container`.
  Do not wire one to the other without deliberately giving up the shared
  container family.
- Light mode does not change the secondary hue rules. It changes the surface
  ladder (`app_surfaces()` in `lucid_palette.py`), tone direction and the
  tertiary tone (42 instead of 80).
- `payload/skwd-wall-v2/matugen/templates/` is a separate template set used
  when skwd owns theming (`features.matugen` is off in the shipped
  `config.json`). It is not part of the active matugen config.
